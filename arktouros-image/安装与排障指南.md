# Arktouros SQLite 一体化安装与排障指南

本安装包适用于 Linux x86_64（amd64），包含前端、大屏、Java 后端及 SQLite 存储，可在已安装 Docker Engine 的机器上离线部署。部署过程不需要下载 Java、npm 依赖或 Elasticsearch，不使用 Elasticsearch 证书，也不再使用容器内 systemctl。

## 首次部署

将整个 ZIP 解压到一个固定目录，不要只复制镜像 tar。建议使用不含空格的目录名。在该目录打开终端：

```bash
docker version
bash ./start-arktouros-all-in-one.sh -i 192.168.1.100
```

将 `192.168.1.100` 替换为部署机器的实际 IPv4。浏览器在另一台电脑上时，必须使用客户端可访问的服务器地址，不能填写 `127.0.0.1`。`-i` 会更新前端与大屏的两个地址配置文件；不传时保留文件现有值，初始值是 `127.0.0.1`。脚本直接使用 `docker run`，无需 `docker-compose` 命令，也无需 `docker compose` 插件。`docker-compose.yaml` 仅作为可选的人工部署配置保留。

脚本校验镜像 SHA256、导入镜像、启动容器并等待后端/前端/大屏健康检查。首次启动通常需要几十秒；最多等待约 3 分钟，失败会返回非零退出码并输出日志。镜像标签固定为 `arktouros-all-in-one:sqlite`，不需要登录镜像仓库。

访问地址：

| 功能 | 地址 |
| --- | --- |
| 前端 | `http://服务器IP:50052/#/main/default` |
| 前端备用入口 | `http://服务器IP/` |
| 大屏 | `http://服务器IP:50053/` |
| 后端接口 | `http://服务器IP:50050/api/v0` |

默认数据库为空，首次进入页面没有业务数据是正常情况。默认接收器是离线 Arktouros JSON；TCP 50049、gRPC 50051 端口映射保留，但只有配置对应接收器后才监听。不要把“离线模式下 TCP/gRPC 端口不通”当成启动失败。

## 手动导入 Arktouros TXT 示例

`examples/arktouros-demo.txt` 是 UTF-8 文本，每行一个符合 Arktouros 格式的 JSON 对象。它不是 SQLite 数据库文件；交付 ZIP 内的 `db/` 为空。示例数据完全为合成数据，不包含生产资料。

服务启动后，在 Windows 中把 `examples\arktouros-demo.txt` 复制到 `arktouros-apm-api\input_logs\` 即可。Linux 下等价操作：

```bash
cp examples/arktouros-demo.txt arktouros-apm-api/input_logs/arktouros-demo.txt
```

等待几秒后，输入文件会被重命名为 `ARKTOUROS-READ-arktouros-demo.txt`。前端命名空间选择 `default`，可看到：

- 4 个服务：`demo-gateway`、`demo-order`、`demo-payment`、`demo-database`。
- 30 条跨服务调用链，共 120 个 Span；gateway → order → payment → database。
- 60 条带 traceId 的日志，其中 2 条 ERROR。
- 240 个 Gauge 数据点，各服务均有 `cpu_usage` 与 `memory_usage` 两个指标。
- 1 个异常结束 Span（endTime=-1）和 1 个模拟长耗时 Span。

示例时间在出包时更新；以后使用旧包时，若默认时间范围内看不到指标，请扩大时间范围。也可以使用可选的 `bash ./import-example.sh` 将示例时间更新到当前后导入，但手动复制 TXT 不依赖这个脚本。

## 页面清空与重新导入

前端的四个删除按钮分别删除日志、数值、链路或全部数据。单类型删除保留其他类型和服务目录；服务总览的“删除所有数据”同时清空服务目录。

清空完成后无需重启服务，也不要删除数据库文件或 `index.txt`。重新从 `examples/` 复制原始 TXT 到 `input_logs/`，接收器会再次导入。不能复制已经带 `ARKTOUROS-READ-` 前缀的文件作为新输入。未清空时重复导入会增加日志和指标记录，因此需要先确认页面已清空。

```bash
# 点击页面“删除所有数据”后，再执行：
cp examples/arktouros-demo.txt arktouros-apm-api/input_logs/arktouros-demo.txt
curl 'http://127.0.0.1:50050/api/v0/services?pageNum=1&pageSize=10'
curl 'http://127.0.0.1:50050/api/v0/logs?pageNum=1&pageSize=10'
```

正确结果包含 `code: 2000`，服务总数为 4，日志总数为 60。原始 TXT 始终留在 `examples/`，不会被接收器修改。

## 接入自己的离线数据

核对 `arktouros-apm-api/config/application.yaml` 中：

```yaml
instance:
  active:
    dataReceiver: jsonFile
    sinker: sqlite
    searchMapper: sqlite
    scheduledJob: sqlite
    operation: sqlite
receiver:
  file:
    json:
      type: arktouros
      logDir: /usr/local/arktouros-apm-api/input_logs
      indexFilePath: /usr/local/arktouros-apm-api/input_logs/index.txt
```

不要用这段片段覆盖整个配置文件。`type` 应与采集文件格式匹配；现有 sytel 输入可切换为 `sytel`。修改 YAML 后执行 `docker restart arktouros-all-in-one`。

先在输入目录之外写完文件，再一次性移动到 `arktouros-apm-api/input_logs/`，避免接收器读到未写完的文件。该目录只放数据，不要放说明文档、ZIP 或数据库。接收器读取后会把文件重命名为 `ARKTOUROS-READ-原文件名` 并更新 `index.txt`。不要随意删除索引或去掉已读前缀，否则日志/指标可能重复导入。

## 端口与文件映射

保留原包除 Elasticsearch 外的全部有效端口：80、50049、50050、50051、50052、50053；不再映射 9200/9300。

| 宿主机相对路径 | 容器路径 | 用途 |
| --- | --- | --- |
| `arktouros-apm-api/config` | `/usr/local/arktouros-apm-api/config` | 后端配置 |
| `arktouros-apm-api/logs` | `/usr/local/arktouros-apm-api/logs` | 后端日志 |
| `arktouros-apm-api/input_logs` | `/usr/local/arktouros-apm-api/input_logs` | 离线输入和读取进度 |
| `arktouros-ui/arktourosUiConfig.js` | `/etc/nginx/html/arktouros-ui/arktourosUiConfig.js` | 前端地址配置 |
| `arktouros-bigscreen/config.json` | `/etc/nginx/html/arktouros-bigscreen/config.json` | 大屏地址配置 |
| `arktouros-apm-api/db` | `/usr/local/arktouros-apm-api/db` | 新增持久化目录，SQLite 与 H2 队列 |

配置默认从 `db/arktouros.sqlite` 读写遥测数据，`db/apm.mv.db` 为 H2 接收队列；H2 不需要独立服务。数据库目录需要可写，且应放在本机磁盘。运行中的 SQLite 可能同时存在 `-wal` 和 `-shm` 文件，不能把它们当成过期锁直接删除。

## 停止、重启与备份

```bash
docker stop --time 45 arktouros-all-in-one
docker start arktouros-all-in-one
docker restart arktouros-all-in-one
docker ps --filter name=arktouros-all-in-one
docker logs --tail 100 arktouros-all-in-one
docker exec arktouros-all-in-one supervisorctl status
```

正常情况下 supervisorctl 显示 `apm`、`nginx` 为 RUNNING。不要执行旧版指南中的 `systemctl start elasticsearch`、删除 ES 锁等操作。

备份时停止容器，将整个安装目录或至少 `config/`、`db/`、`input_logs/`、两个前端配置文件一并复制，再启动。数据库位于宿主机挂载目录，正常停止或重建容器后仍保留。不要在运行时只复制 SQLite 主文件，避免遗漏 WAL 中的数据。

再次运行启动脚本会替换名为 `arktouros-all-in-one` 的旧容器。校验和加载新镜像成功后才会停止旧服务；SQLite 的宿主机挂载目录保留。如果旧容器使用 Elasticsearch，或 SQLite 数据库没有挂载到宿主机，会先把停止后的容器内部文件导出到 `backups/replaced-时间戳/container-rootfs.tar`，同时保存容器 inspect 信息，备份成功才删除旧容器。

新服务健康后，脚本清理本应用已知的旧镜像（包括旧版 `arktouros-all-in-one:0.1` 和被替换容器的镜像）；仍被其他容器使用的镜像会保留。脚本不运行全局 prune，也不删除挂载目录或 Docker volumes。`docker export` 不包含挂载卷内容，旧 volumes 和宿主机数据需要单独保留。旧 ES 索引不会自动迁移到 SQLite。

更新时应在同一安装目录运行脚本以复用数据挂载。更换安装目录意味着使用另一份 `db/`，不会自动搬移旧目录的数据。

## 常见故障

| 现象 | 检查与处理 |
| --- | --- |
| Docker 命令不存在或无法连接 daemon | 安装/启动 Docker；检查当前用户是否具有 Docker 权限，必要时使用 sudo。 |
| SHA256 校验失败 | 文件传输不完整或被修改，重新传输镜像和对应校验文件，不要跳过校验。 |
| 端口占用 | 用 `ss -lntp` 检查 80、50049～50053，停止冲突服务；保持端口不变时不要并行运行旧容器。 |
| 启动超时 / unhealthy | 查看 `docker logs --tail 200 arktouros-all-in-one`、`supervisorctl status` 和 `arktouros-apm-api/logs/arktouros.log`。核对 YAML、目录可写、磁盘空间。 |
| SQLite database is locked | 确认只有一个 APM 实例写该数据库，目录不是网络盘。不要删除数据库或 WAL；停止全部写入实例后再检查。 |
| 前端能打开但请求失败 | 核对配置里的服务器 IP，不要在远程浏览器使用 127.0.0.1；确认防火墙允许相关端口。更改 IP 后硬刷新浏览器。 |
| 大屏没有曲线 | 先选择示例服务；检查是否成功导入数据、时间范围是否包含样本，以及 config.json 的 backendUrl 是否为本包默认的 http 地址。 |
| 文件不导入 | 检查文件格式与 type、一行对象是否完整、文件是否已带 ARKTOUROS-READ- 前缀，并查看后端日志。 |
| 修改 application.yaml 不生效 | 修改的是宿主机映射目录下的文件后，执行 `docker restart arktouros-all-in-one`。 |

只在纯测试环境需要“彻底重置”时使用新的空安装目录或备份后清理测试数据。不要将有生产数据的目录当作示例测试目录清空。对外发送本安装包前应保持 `db/`、`logs/`、`input_logs/` 为空，示例留在 `examples/` 下按需导入。
